# 해파리 조기경보 DB (MySQL 8.0)

데이터 보정 (이미 반영됨)
- CSV에는 `전처리_보정.py`의 규칙이 이미 적용되어 있음 (다시 실행해도 결과가 같음)
  - 규칙 1: 앞뒤 주와 동떨어진 수온 이상값 결측 처리 (포항 2018-12-10 주 1.8℃)
  - 규칙 1-2: 시간별 원자료로 확인한 부이 고장 구간 결측 처리 (포항 2018-12-03 주)
  - 규칙 1-3: 습도 10% 미만 결측 처리 (덕적도 2023-07-03 주 2.5%)
  - 규칙 2: 시군 4곳 추가(부산 영도구·남구·강서구, 울산 북구), 설문 지점 15곳 좌표·시군 보정
- 출현기록의 빈칸: 2017년 이후 원자료는 미목격(0%)을 빈칸으로 기록 (SQL2 뷰에서 처리)
  ① 같은 보고·권역에 값이 하나라도 있으면 빈칸 = 0%
  ② 세 어종 모두 빈칸이어도 같은 해 같은 권역에 앞·뒤 보고 값이 모두 있으면(시즌 중간) 0%
  ③ 그 외(시즌 시작·끝 주, 보고 중단 권역)는 결측

실행 순서
1. MySQL Workbench에서 `SQL1_create_tables.sql` 실행 (DB 이름: jellyfish, 문자셋 utf8mb4)
2. `load_db.py`의 비밀번호를 고치고 `python load_db.py` 실행 → CSV 11개 적재 (삽입 SQL, 트랜잭션)
3. `SQL2_views.sql` 실행 → 뷰 7개 생성
4. `SQL3_queries.sql`로 질의 확인 (질의 8개)

예측 넣기 (머신러닝 완료 후)
- `03_머신러닝/서비스`에서 `python 서비스_로지스틱.py 전체 --db --저장` → 같은 모델명 예측을 지우고 새로 넣음
- 이후 `서비스/결과/권역예측_Logistic_v1.csv`를 이 폴더의 `11_권역예측.csv`로 덮어써 두기

주의: `load_db.py`는 빈 DB에 한 번만 실행 (다시 실행하면 기본키 중복 오류). 처음부터 다시 만들려면 `DROP DATABASE IF EXISTS jellyfish;` 후 1번부터

테이블 11개: 권역, 시군, 해수욕장, 관측소, 관측자료, 주간보고, 어종, 출현기록, 설문지점, 설문응답, 권역예측(비어 있음. 머신러닝 완료 후 03_머신러닝/서비스의 db_권역예측_저장.py로 예측 CSV를 넣음)
뷰 7개: v_권역기준곡선, v_관측소평년, v_해수욕장가중치, v_해수욕장주간위험도, v_해수욕장예측위험도, v_설문권역집계, v_학습데이터

CSV는 UTF-8(BOM 포함)으로 저장되어 엑셀에서 더블클릭해도 한글이 깨지지 않음. load_db.py는 utf-8-sig로 읽어 BOM을 자동 처리함.
명령줄 클라이언트로 SQL 파일을 실행할 때는 `--default-character-set=utf8mb4` 옵션을 붙일 것.
