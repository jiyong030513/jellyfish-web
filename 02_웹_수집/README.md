## 처음 실행 순서
1. DB 구축: 엔디비_최종테이블_10에서 SQL1 → 전처리_보정.py → load_db.py → SQL2
2. 라이브러리 설치: `pip install -r requirements.txt`
3. db.py 확인: MySQL 비밀번호, 국립수산과학원 키(NIFS_KEY), 기상청 키(KMA_KEY), 머신러닝 폴더(ML_DIR = 03_머신러닝\서비스)
   - 비밀번호는 db.py 한 곳에만 있음 (서비스_예측.py도 db.py를 읽음)
   - 제출·공유할 때는 비밀번호와 키를 지우기
4. 최신 자료 채우기: `python update_all.py` (아래 "매주 갱신" 참고)
5. 웹 실행: `python app.py` (또는 VS Code에서 app.py 열고 ▶) → 브라우저가 열림 (http://localhost:8501)
   - 끌 때는 터미널에서 Ctrl + C
   - DB 내용을 바꾼 뒤에는 화면 왼쪽 "DB 다시 불러오기" 버튼
   - 주소로 바로 열기: http://localhost:8501/?beach=B149&date=2023-08-10 (해수욕장ID, 날짜)

## 매주 갱신 (update_all.py)
`python update_all.py` 한 번이면 아래 순서로 진행됩니다. 입력할 것은 없습니다.

| 단계 | 하는 일 | 실패하면 |
|---|---|---|
| 0. 준비 | DB 접속 확인, mysqldump 백업 (`백업\`) | **전체 멈춤** (아무것도 쓰지 않음) |
| ① 해파리 | collect_reports.py: 새 주간보고 PDF → 주간보고·출현기록 INSERT (이미 있는 보고는 건너뜀) | 이유 출력 후 ②로 계속 |
| ② 부이 | collect_buoy.py: 지점별 마지막 주부터 오늘까지 → 관측자료 INSERT/UPDATE | rollback, 기존 자료로 ③ 계속 |
| ③ 예측 | `03_머신러닝\서비스\서비스_예측.py` (저장된 모델로 예측만, 재학습 없음 → 권역예측 저장) | 이유 출력. ML_DIR이 비어 있으면 건너뜀 |
| ④ 요약 | 추가된 보고 수, 갱신된 주 수, 최신 예측 기준일 | — |

- 화면 출력은 `추가수집\갱신로그\update_날짜.log`에도 저장됩니다.
- 실패한 단계가 있으면 종료 코드 1로 끝납니다 (작업 스케줄러의 "마지막 실행 결과"에서 확인).

### 윈도우 작업 스케줄러에 등록 (매주 금요일 오전 10시)
명령 프롬프트(cmd)를 열고 한 줄로 실행합니다. python 경로는 `python -c "import sys;print(sys.executable)"`로 확인한 값입니다.
```
schtasks /Create /TN "해파리DB_주간갱신" /SC WEEKLY /D FRI /ST 10:00 /TR "\"C:\Users\이지용\AppData\Local\Programs\Python\Python312\python.exe\" \"C:\Users\이지용\Desktop\엔지니어링DB_프로젝트\02_웹_수집\update_all.py\""
```
- 바로 한 번 시험: `schtasks /Run /TN "해파리DB_주간갱신"`
- 등록 확인: `schtasks /Query /TN "해파리DB_주간갱신" /V /FO LIST`
- 삭제: `schtasks /Delete /TN "해파리DB_주간갱신" /F`
- 컴퓨터가 켜져 있고 로그인한 상태, MySQL 서비스가 켜져 있어야 실행됩니다.

## 해파리 주간보고 수집 (collect_reports.py)
국립수산과학원 OpenAPI는 2024년 5월까지만 출현율 숫자를 주고, 그 뒤 주간보고는 PDF로만 올라옵니다.
collect_reports.py가 PDF의 "붙임 3. 각 지역별 해파리 출현율(%)" 표를 읽어 DB에 추가합니다.
- 단독 실행: `python collect_reports.py` (이미 넣은 보고는 건너뜀, 여러 번 실행해도 안전)
- 2025년부터 보고서가 전남을 하나로 적으므로 같은 값을 전남(서해)·전남(남해)에 모두 넣음
- 검증: `python verify_reports.py` → PDF와 DB 값을 대조해 검증결과.csv, 검증.html 생성

## 기상청 부이 수집 (collect_buoy.py)
- 지점 7곳: 22101 덕적도, 22103 거문도, 22104 거제도, 22105 동해, 22106 포항, 22108 외연도, 22183 신안
- API: 기상청 API허브 `kma_buoy2.php` (지점별로 1개월씩 나눠 요청, 실패하면 3번 재시도)
- 기간: 지점별 DB 관측자료의 마지막 주(MAX(시작일))부터 오늘까지.
  최초 구축 자료(2025-12-31까지)는 다시 계산하지 않음 → 첫 실행은 2026-01-01부터
- 저장: 없는 주는 INSERT (관측ID는 기존 최댓값 다음 번호, W04453부터), 이미 있는 주(진행 중인 주 포함)는 다시 계산해 UPDATE (관측ID 유지).
  한 트랜잭션으로 처리하고 오류가 나면 rollback
- 열 매핑: 풍향=WD1, 풍속=WS1, 최대돌풍=WS1_GST (센서1만 사용, 비면 그 시간은 결측 → 학습 자료와 같은 기준), 기압=PA, 습도=HM, 기온=TA, 수온=TW,
  최대파고=WH_MAX, 유의파고=WH_SIG, 평균파고=WH_AVE, 파주기=WP, 파향=WO
- 주간 집계 규칙 (최초 구축 05_관측자료와 같음)
  - 정각(분=00) 자료만 사용 → 1시간 간격 (지점마다 10분·30분 간격이 달라서)
  - 한 주 = 월~일. 1월 1일이 주 중간이면 1월 1일부터 새 주. 주차 = 1월 1일이 든 주를 1주로 하는 순번
  - 평균: 풍속·기압·습도·기온·수온·유의파고·평균파고·파주기 / 최댓값: 최대돌풍·최대파고 / 각도 평균: 풍향·파향
  - 결측(-99) → NULL, 돌풍 60 m/s 초과 · 습도 10% 미만 시간값 제외,
    물리적 범위 밖 값 제외 (파고 25 m 초과, 기압 900~1080 hPa 밖 등. 원본에 최대파고 712 m 같은 오류가 있음)
- 옵션
  - `python collect_buoy.py --dry-run` : 계산만 하고 DB에 쓰지 않음 (결과를 화면에 표로 보여 줌)
  - `python collect_buoy.py --dry-run --start 2025-12-01 --end 2025-12-31` : 기존 주간값과 비교용
  - `--stn 22101 22103` : 일부 지점만, `--no-backup` : 백업 생략
- 검증 (2026-11-08): 같은 방식으로 2025-12-01~22 주(7지점 28행)를 다시 계산하면 최대돌풍·기압·습도·수온·최대파고·유의파고·파향은 모두 일치,
  나머지도 대부분 일치(기온·파주기 차이 0.07 이하). 예외: 외연도(22108) 12-01~15 주 풍속은 기존 값이 있지만 센서1이 비어 있어
  원자료로 재현되지 않음 (최초 구축 자료라 그대로 둠)

## 머신러닝 예측 (03_머신러닝\서비스\서비스_예측.py)
- 05_서비스_로지스틱.ipynb와 같은 코드. 설정 고정: SOURCE="db", SAVE_TO_DB=True, USE_SAVED_MODEL=True
- `python 서비스_예측.py` : 저장된 모델로 예측 → 결과 CSV → 권역예측 테이블 (같은 모델명 예측을 지우고 새로 넣는 한 트랜잭션)
- `python 서비스_예측.py --dry-run` : DB에 저장하지 않음. CSV는 `결과\권역예측_Logistic_v1_dryrun.csv`에 따로 저장
- `python 서비스_예측.py --학습` : 다시 학습 (1년에 한 번). 기존 모델은 `모델\logistic_v1_백업_날짜.joblib`로 복사해 둠
- 검증 (2026-11-08 dry-run): 기존 결과 CSV 5,547행과 급증확률이 모두 같음.
  예측 7,341행 (2,447개 권역·주 × 3기간), 가장 최근 기준일 2026-10-30.
  2024-05-24 경기 3행은 새로 생김 (뒤에 2024-06 보고가 들어와 뷰 규칙상 빈칸이 0%가 됨)

## 웹 화면 (app.py)
- 왼쪽: 날짜, 해수욕장 검색, 지도 색 기준(평년 출현율 / 예측 위험 지수), 예측 기간(1·2·4주)
- 지도: 해수욕장 270곳을 위험 등급 색으로 표시. 점을 누르거나 검색하면 그 해수욕장으로 이동하며 위험도 표시
- 오른쪽: 평년 출현율(어종별), 권역 최근 보고·k주 뒤 예측 위험 지수, 해수욕장 가중치, 연결 관측소
- 아래: 5~12월 평년 출현율 그래프, "이 화면에서 쓴 SQL 보기"

### 날짜 기준
- 평년 출현율: 선택한 날짜의 월·주차(1~7일=1주 … 22일~말일=4주). 5~12월만 있음
- 1·2·4주 뒤 예측: 선택한 날짜에서 1·2·4주 뒤의 월·주차에 권역이 대량출현(통합 50% 이상)일 확률 × 해수욕장 가중치.
  확률은 2014~2024년 주간보고에서 그 주에 대량출현이었던 비율 (보고 2건 미만인 칸은 같은 달 비율)
- 선택한 날짜 14일 안에 실제 주간보고가 있으면 그 보고를 반영한 모델 예측(권역예측 테이블)도 함께 표시
- 속도: 앱을 시작할 때 뷰를 한 번만 읽어 오고, 클릭·검색은 읽어 온 자료에서 바로 찾음

## 지켜야 할 것
- 테이블 구조(SQL1)와 뷰(SQL2)는 바꾸지 않음. 스크립트는 데이터 INSERT/UPDATE만 함
- 계산값은 뷰라서 데이터만 추가하면 화면이 자동으로 갱신됨
- 문제가 생기면 백업으로 되돌리기: `mysql -u root -p jellyfish < ..\백업\jellyfish_날짜.sql`
